# SMUniversal Lab Suite

Modular Tkinter apps for SMU-based measurements. One repository holds all
instrument drivers; each measurement is a self-contained experiment that
plugs into a shared app shell.

**Documentation: https://jcgutierrezg.github.io/SMUniversal_Lab_Suite/** - a user guide for running the
measurements, and the developer notes, searchable, built from `docs/`.

**This file routes. It holds no reference material**, because a landing page
that also explains the instruments is a landing page that disagrees with the
instrument notes within a month.

## Install

### A bench PC, from nothing

Windows 10 or 11. About ten minutes, most of it downloads.

1. **Install Git** from <https://git-scm.com/download/win>, keeping the
   default options.

2. **Install uv.** In PowerShell:

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```

   Close PowerShell and open a new one, so `uv` is found. There is no separate
   Python to install: uv fetches the version the suite needs by itself.

3. **Install a VISA library, if this PC has a GPIB controller** - NI-VISA or
   Keysight IO Libraries Suite. GPIB goes through VISA by default. A PC with
   only USB and serial instruments can skip this step. (A PC that drives an NI
   GPIB-USB-HS adapter directly, with no NI software, has a different step:
   see [the direct GPIB-USB-HS transport](docs/architecture/direct-gpib-usb-hs.md).)

4. **Get the suite.** In PowerShell, in the folder it should live in:

   ```powershell
   git clone https://github.com/jcgutierrezg/SMUniversal_Lab_Suite.git
   cd SMUniversal_Lab_Suite
   ```

5. **Install it and put it on the desktop:**

   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\make_shortcut.ps1
   ```

   This installs everything the suite needs, then puts **SMUniversal Lab
   Suite** on the desktop. Add `-StartMenu` to put it in the Start menu too.
   If the install fails, the reason is printed here rather than discovered
   later by clicking an icon that does nothing.

6. **Check it.** Double-click the icon: the window chooser opens. Open a
   measurement window and press **Refresh** in *Instruments* - the connected
   instruments are listed by name. If one is missing, run
   `uv run tools/visa_doctor.py` in the suite's folder; it says why.

**Always start the suite from the icon**, not from a console. It opens with no
console window on purpose: closing a console kills Python before the window
can switch the instruments off. The window's own close button is the one that
puts them away.

### Updating

In the suite's folder:

```powershell
git pull
```

The next double-click runs the new code and installs anything the update
added.

### If it will not start

A failed launch says so in a dialog, and the details are written to
`%LOCALAPPDATA%\SMUniversal_Lab_Suite\launcher.log`. Running `uv sync` in the
suite's folder repairs an incomplete install.

### For development

```powershell
uv sync
uv run python main.py
```

One install for every machine, with every instrument's library in it - the
miniSMU's, the USB layer, the direct GPIB-USB-HS driver. There are no optional
extras to remember: each library is imported only when its own instrument is
chosen, so having them all changes nothing for a bench that owns none of
those instruments. See [packaging](docs/workflow/packaging.md). Tests are in
[tests/README.md](tests/README.md).

## First run

```powershell
uv run python main.py                # chooser
uv run python main.py vdp_hall       # Van der Pauw and Hall in one window
uv run python main.py iv_sweep
uv run python main.py ossila_4pp
uv run python main.py fixed_source
uv run python main.py plotter       # plot saved CSVs from any experiment
```

`vdp_hall` is the one to use at the bench. A Van der Pauw run always
immediately precedes a Hall measurement on the same mounted sample with the
same contacts, so the two share one window: one SMU connection, one sample
name and thickness, one temperature stage, one save folder. The tabs are two
views onto one session, not two programs — and Hall is not offered on its
own, because a Hall window that cannot obtain a sheet resistance is a trap
rather than a choice. See
[the handoff](docs/experiments/hall.md#the-handoff).

No hardware? Pick **Demo** in the transport dropdown, or accept the offer
when a connection fails. Demo goes through the same connect path as a real
instrument — see [the dummy SMU](docs/instruments/dummy-smu.md).

## Safety

**Nothing here clips an out-of-range request.** `app.check_source_point()`
validates the operating point against the connected driver's declared limits,
including a power envelope, and refuses outright. Range dropdowns are
repopulated from the instrument on connect, so unreachable values are never
offered. A wrong `LIMITS` therefore matters:
[the safety gates](docs/architecture/app-shell.md#6-safety-gates).

**"Output off" does not necessarily disconnect the sample.** By default it
sources 0 V into it rather than opening the output relay, because the relay
has a finite number of operations in it. The High-Z option is what opens it.

**A run bounded by a timer is a safety property, not a convenience.** Fixed
sourcing vs time is bounded by real elapsed time so that nobody walks away
from a live fixture:
[fixed sourcing vs time](docs/experiments/fixed-source-vs-time.md).

**Disconnect everything from the outputs before a checkup.**
`tools/smu_checkup.py` sources real levels and prompts to confirm this first:
[running a checkup](docs/guide/good-data/running-a-checkup.md).

## Tests

```powershell
uv run python run_tests.py --all
```

That is the suite command, and a green run of it is the only accepted
evidence that the suite is green. Plain `pytest` on a single file is fine
while developing that file; it is not a substitute for the runner, which
gives each GUI file its own process. The reasoning, the markers and the
mutation rule are in [tests/README.md](tests/README.md).

Two gates run alongside it, in CI and locally, and both are green on the tree
today — which is what makes them enforceable:

```powershell
uv tool run ruff check --no-cache .
uv run mypy
```

Documentation pages that are generated must be rebuilt in the same patch that
changes what they derive from:

```powershell
uv run python tools/build_docs.py
```

## The measurements

| Experiment | Produces | Note |
|---|---|---|
| Van der Pauw | sheet resistance and resistivity; supplies Hall | [van-der-pauw](docs/experiments/van-der-pauw.md) |
| Hall effect | carrier density, mobility, carrier type | [hall](docs/experiments/hall.md) |
| IV sweep | voltage or current sweeps, optional linear fit, periodic bias mode | [iv-sweep](docs/experiments/iv-sweep.md) |
| Ossila four-point probe | sheet resistance, resistivity, conductivity | [ossila-4pp](docs/experiments/ossila-4pp.md) |
| Fixed sourcing vs time | one held level sampled against the clock | [fixed-source-vs-time](docs/experiments/fixed-source-vs-time.md) |

Runs are **not** written to disk as they finish — nothing is saved until you
press **Save snapshot → CSV**, so a spoiled run can be deleted without ever
leaving a file behind. What a saved file contains, and why saving is a
snapshot, is [house rule 3](docs/rules/03-no-auto-save.md).

## Instruments

`smuniversal_lab_suite/drivers/registry.py` is the list that matters. Which instrument suits a
sample, and whether its driver has been checked against that instrument
recently, are both **generated rather than written**:
[choosing an SMU](docs/guide/instruments/index.md) and
[checkup owed](docs/open/checkup-owed.md).

Read the second one before trusting a driver. It distinguishes a driver that
is *stale* — checked once against its instrument, but the code has moved
since — from one that is *unverified*, meaning it has never met the
instrument at all. Those are different risks and prose that flattens them
into "not commissioned" is worse than no prose.

## How it fits together

```
experiments/  →  drivers/  →  core/transports/
```

Dependencies point one way only: nothing in `core/` imports from
`experiments/`, and no driver imports an experiment. What each module is for,
and what breaks without it, is
[the architecture index](docs/architecture/index.md).
